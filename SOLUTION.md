# Решение

## Сколько заняло

Точное время не фиксировалось. Время на ручную проверку в браузере ещё не включено.

## Что сделано и что не успел

Реализованы загрузка с сервера, карточки матчей, состояния загрузки/ошибки/пустого списка, повтор запроса, фильтры и обновление. Подключено избранное, исправлен счётчик времени после обновления. Новых зависимостей нет.

Дополнительно выбраны тесты логики фильтров: они проверяют спорные статусы и пограничные случаи на данных задания. Команды проверки: `npm run typecheck` и `npm test` (6 тестов проходят). Expo запускается через `npm run web`; ручная проверка интерфейса пока не завершена.

## Решения

- «Предстоящие»: `scheduled` и `postponed`, поскольку перенесённый матч ещё предстоит сыграть. «Завершённые»: только `finished`. Текущие (`live`), отменённые и неизвестные статусы видны в «Все»; неизвестный статус обозначен как «Статус уточняется».
- Фильтрация опирается на статус сервера, а не дату: в примере есть `scheduled` с уже прошедшим временем. Локально переопределять статус было бы ненадёжно.
- Счёт проверяется на наличие объекта: `0:0` отображается корректно. Если даты нет или она некорректна, выводится «Дата уточняется». Время форматируется через `toLocaleString('ru-RU')` без фиксированного `timeZone`, то есть в часовом поясе устройства. Для `live` показывается минута, включая нулевую.
- В заготовке `MATCHES_URL` содержал `OWNER/REPO`; заменён на публичный адрес исходного репозитория Interlabs22/test-app. Данные по-прежнему загружаются по HTTP, без подмены локальным JSON.
- При ошибке обновления предыдущие данные остаются видимыми с пояснением. Метка успешного обновления меняется только после успешного запроса. Запрос имеет тайм-аут 15 секунд; при размонтировании и замене запроса выполняется отмена, устаревший ответ не перезаписывает состояние.

## Баги из части 2

1. Звёздочки: `indexOf` возвращает `-1` для отсутствующего id и `0` для первого найденного, поэтому `Boolean(indexOf(...))` давал противоположный результат в этих случаях. Кроме того, `push`/`splice` изменяли исходный массив, и React получал прежнюю ссылку, из-за чего обновление могло не отрисоваться. Использованы `includes` и функциональный `setFavorites`, возвращающий новый массив; состояние избранного общее для экрана и передано в `FlatList.extraData`.
2. «Обновлено N сек назад»: интервал замыкал начальное `seconds = 0` и каждый раз устанавливал `1`; эффект не зависел от `since`, не сбрасывал отсчёт и не очищал интервал. Теперь число секунд вычисляется из разницы текущего времени и `since`, эффект реагирует на новую метку времени и очищает интервал. Это также позволяет корректно догнать прошедшее время после задержки таймера.

## Как я использовал ИИ

Для реализации использован Codex: агент изучил код и данные, реализовал экран, исправил ошибки и подготовил тесты. Автоматически выполнены проверка TypeScript и 6 тестов фильтрации, статусов и времени в UTC/Europe/Moscow.

Попытка агента передать порт через `npm run web -- --port 8082` в PowerShell привела к неверному аргументу; это было видно по сообщению Expo о пути проекта. Повторный запуск обычной командой `npm run web` запустил Metro. Встроенный браузер открыл по localhost другой сервис, а проверка через браузер Windows была остановлена ограничением инструмента: эти попытки не считаются ручной проверкой интерфейса.

Перед сдачей остаётся вручную проверить: три фильтра, независимое переключение звёздочек, счёт `0:0`, перенесённый матч без даты, рост таймера и его сброс после обновления; при отключённой сети — ошибку и повтор после восстановления подключения. Пустое состояние нужно проверить на ответе с `matches: []`. После проверки следует обновить этот раздел фактическими результатами.
